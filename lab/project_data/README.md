# Public project observations and shadow routing protocol

Each receipt records an actual audit of an installed open-source distribution. Source identities include the wheel RECORD, WHEEL, METADATA and the specific implementation file and symbol. Checked files had a declared SHA-256 and resolved inside the distribution root. Missing, mismatched and excluded entries are counted separately. A mismatch describes this installation and does not establish its cause. Python parameters are names from the installed source declaration, including variadic names, without defaults or annotations.

Questions in each split are author-written evaluation instruments. The measured values come from the audit. Each question has four project documents derived from separate parts of its receipt, with a reproducibly shuffled document order. Some natural queries exceed the host's lookup grammar. Their expected result remains the measured answer, so abstentions count as missed useful outcomes.

For each training question the runner tries each of the four source proposals in a fresh profile through real import, Primary, Research and Finish. A training target is positive only if the actual task completes with the independently specified receipt value, document identity, exact span, integrity and relevance. An audit result is publicly reproducible author evidence. The questions are authored and all ten projects share an installation-audit workflow. These are limited tests of generalization to unfamiliar upstream codebases. They do not measure organic user adoption, general coding skill, or independent custody.

The trainer reads only the pinned public training and validation partitions. It has no arbitrary manifest argument. Model inputs are the question and document text. Split names, family labels, expected answers and protected expectations are excluded as model features. The six features measure TF-IDF document similarity and maximum key-level TF-IDF, overlap, character trigram and phrase agreement. The learned comparators are logistic regression and an original six-hidden-unit tanh network. Fits use one CPU BLAS thread, 600 full-batch updates, learning rate 0.25 and L2 coefficient 0.001. The native seed set is 11, 37 and 73. Validation selects by useful deliveries, wrong deliveries, Brier score and then proximity to cutoff 0.5 and lower seed. Thresholds tested are 0.35, 0.5 and 0.65. The full deterministic host and untrained query/document TF-IDF provide additional controls.

The checks-only replay records the real host outcome for each distinct proposal with the entire project available to Research. Policies choosing the same action share its measured outcome. Timing separates Python scoring from the host and cold process. Calibration uses success of the top proposed document before thresholding. Memory includes fit allocations traced by Python and the host working set sampled by the probe. The archived checkpoint is advisory and absent from desktop packaging. Public constructed stress tests, the old template routing suite and any external custodian tests are reported separately and are ineligible for fitting. The historical host is compared on the same held-out inputs.

For independent review, keep new suite inputs and expectations outside this repository under custodian control. Replay source hashes or fresh real work and disclose shareable aggregates, costs, and failures. A learned policy requires independent improvement over both the active host and strong linear baseline before promotion can be considered.
