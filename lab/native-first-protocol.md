# NEXT-016 through NEXT-020 native-original experiment protocol

The unit of generalization is an upstream project family. The task is selecting an authorized Markdown evidence source for one imported project fact. An exact independently verified host completion under the proposed restriction earns a positive label. A withheld answer or an incorrect delivery earns a negative label. Input errors or malformed receipts abort acquisition. A withheld request can still be answerable through another action. The training target is the proposed action's outcome.

- **NEXT-016.** Reobserve the existing pinned distribution-audit projections. Add new observations for pandas and python-dateutil to training, pycparser to public evaluation, and reportlab and pdfplumber to a separate future acquisition pool. Requests are author-designed questions over measurements from named public distributions already installed locally. No network access, private sources, source execution, fixture labels, or copies of conversation/qualification expectations. Each question gets the unrestricted host, explicit abstention, and each document restriction. Retain safe withholds and any wrong deliveries, with separate counts. Normalize request identity and pin exact source inputs, archive permissions, family roles and outcomes. Reject repeated normalized requests and cross-family source/receipt duplicates. The protected comparison is evaluator-owned, outside the author checkout and accessible only to a separate scoring entry point.
- **NEXT-017.** Use existing six text/claim similarity features, fit IDF on train only, compare a random 6→8→1 tanh network (65 parameters), logistic regression (7 parameters), TF-IDF and unrestricted host. Use seeds 11, 37 and 73 for the nonlinear candidate, and 11 for logistic. Fixed 600 full-batch Adam steps at learning rate 0.03. Use inverse frequency class weighting from train. Select cutoff from 0.35, 0.50, 0.65 by validation useful deliveries, wrong deliveries, probability Brier, proximity to 0.50, then smallest seed. Require both labels. Record training and validation losses, reported probabilities, fit cost, weights and optimizer. Public evaluation is diagnostic and is never used for selection.
- **NEXT-018.** The original Primary Master learns whether a specialist's top-ranked proposal would yield a verified completion. Inputs are top probability, runner-up gap, claim-coverage fraction and document count. Train on one prediction per train request with the specialist fit without that entire family. Validation uses the frozen full specialist. Train a random 4→6→1 network (37 parameters) and a five-parameter logistic gate. Keep hyperparameters and selection order as above. Below the gate, route to unrestricted host. Compare with specialist-only, host, a confidence-only gate and logistic gate. Report gate true/false proposals, false positives/negatives, fallbacks and downstream outcomes.
- **NEXT-019.** Provide a read-only native-original local command for a user question and explicitly supplied local .md sources. Trace the Master decision, specialist prediction and host verification. The user must explicitly supply the authorized inputs. Whichever route is proposed, a deterministic host run without the learned restriction remains the user's authoritative result. Report shadow outcomes independently. Compare host, TF-IDF, logistic, specialist-only, and gated cooperation on the same author-public outcomes and actually run the live host checks for user-provided questions. No execution or learned authorization.
- **NEXT-020.** Diagnose the frozen specialist on validation only. If it misses an answerable request, or fails to improve useful completion over the deterministic baseline, fit a fresh candidate on train plus the separately enrolled acquisition families. Reuse seeds and hyperparameters. Verify the previous checkpoint is unchanged. Compare previous, new, host, TF-IDF and logistic on frozen public evaluation. Reject for any new incorrect delivery, any lost verified completion, or no strictly higher useful completion than the strongest baseline. Record safe abstentions, loss, latency and resources. Even a passing public diagnostic remains shadow and promotion-blocked until a fresh evaluator-held comparison and owner authorization. The evaluator gates family/identity overlap, sees private expectations only downstream from inference, and writes reports outside the checkout.

Report per-family correct deliveries, wrong deliveries, abstention or withheld count, model scoring and host timings, memory, input and checkpoint hashes, and failure details. Author diagnostics measure this narrow source-selection task. Reusing several prompts over one project does not multiply the number of independent project observations. Private eligibility and native promotion remain under independent control.
