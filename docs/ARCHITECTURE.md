# Architecture

A single unelevated WPF process calls the trusted C# Engine. Release-pinned arrays supply local neural inference. The offline lab trains and evaluates separately. The outcome probe in the checks executable exercises the same import, submit and finish paths as WPF. The desktop exposes read-only lookup, owner-triggered file import, and source-scoped coding and research views. The optional reference client sends text only to the fixed IPv4 loopback Ollama endpoint after owner opt-in and model selection. It disables proxies and redirection, verifies the selected model inventory digest, and bounds request and response sizes. The reference client has no tools. Verified conclusions come from the deterministic host.

| Owner | Runtime contract |
| --- | --- |
| WorkWindow | Accept request and show persisted attempts, source and comparison. Buttons submit, verify, cancel or export. |
| Engine | Submit a bounded request with a GUID, persist queued state, obtain a model proposal, select the allowed deterministic route and resolve an eligible source. Finish or cancel an existing ID. StopAll cancels every pending review. |
| Routing | Digest- and shape-checked 256-input, 16-hidden, 3-output CPU forward pass. Immutable shadow binding. Active deterministic retrieval proposes pinned records or passages from the authorized project. Whole-request Research verification and host delivery authority are separate decisions. |
| Library and Assets | Rebuild an in-memory catalog from pinned release records on startup. Resolve exact IDs directly. Otherwise identify distinguishing terms across all three records and require a single candidate consistent with the proposed route. Reopen and digest-check a selected record on completion. Scope, revision, type and digest must still match. |
| Documents | The owner selects a local TXT, Markdown, C# or Python file into the active project. Check links, encoding and byte budget, publish immutable file revisions by rename and rebuild passage candidates from the latest owned revisions. Cite profile-relative path, version, digest, line and UTF-16 offsets. |
| Source navigation | Import records the identifier and header of each declaration, its direct type qualifier, and source spans for attached documentation and enclosing context. All related passages carry the definition's source offset within the same revision. Roslyn supplies C# syntax. A bounded lexical scanner tracks Python class and function indentation. Primary proposes within the allowed set. CodeQuestions checks the whole request against the active project, detects duplicate identifiers, and binds signature requests to a selected completed definition. Delivery reopens both the parent receipt and the active source revision. |
| Research | Determine requested keys, check literal support and validity, and compare independent active claims. Bounded studies use an explicit two-to-eight-document selection and pin each selected revision before verification. Persist the plan and evidence for reuse. |
| Relevance | Match the whole original request against question forms supported by the cited handbook revision, or its exact catalog ID. Engine checks this before review and again against the reopened source at delivery. Unrecognized subjects, modifiers and conflicting intents request clarification. |
| Journal | One Windows profile writer holds an exclusive handle. One UTF-8 JSON per task contains input, authority, scope, dependencies, limits, specialist, model, result, evidence, verification, event sequence, memory and time sampling. Validate the full startup inventory before changes. Preserve malformed and pending files in quarantine, then commit each interrupted transition by stage, flush and same-volume rename. Restart completes remaining work. |
| Lab | Offline Python builds a fixed-feature original MLP and linear comparator. The project specialist uses pinned public source-proposal outcomes across separate project families. The trial entry point checks family, request and receipt separation, measures frozen policies, and preserves an experiment receipt when fitting is blocked. The Windows model view reads the pinned receipt. |

Supported transitions are queued → review → completed/cancelled/failed/needs clarification, queued → needs clarification/failed, and queued/review → interrupted on restart. Duplicate task ID with the same request returns its current receipt. Conflicting input is refused. A repeated finish or cancel on a terminal task has no effect. Interrupted work needs a fresh request. The two-step interaction gives the owner a genuine cancellation point before answer publication. Power-loss filesystem durability beyond the exercised process-crash cases is unqualified.

Task history belongs to the local OS user. App-level verifiers detect changed shipped data/model files against digests embedded in the executable. A local user able to modify the binary or local journal is outside that guarantee. The results describe source integrity for a demo fixture, with no external claim authentication. Verification checks are deterministic host operations. CPU time and working-set telemetry are observations, not an OS resource sandbox.

Future extension should add typed actions with explicit permissions and independent validation through this host contract. A future private transport would need authenticated principal mapping and narrower storage ACLs. Move to indexed transactional persistence when multiple writers, long-running jobs or multi-principal scope require it. [Decisions](DECISIONS.md)
