# ATLAS AI — OWNER'S READER GUIDE AND COMPLETE PRODUCT TOUR (v3.3)

**This guide is a navigational companion to the full 73,000-word canonical master, not a replacement or a summary claiming implementation.** It explains the intended ATLAS product in approachable language, where to find its detailed contracts and how to tell tested reality from future ambitions. The entire canonical Markdown and a formatted Word edition are in this transfer package.

## The most important promise

ATLAS stands for **Adaptive Tiered Learning, Analysis & Search**. It should become an owner-controlled, local-first intelligence application whose primary learned capabilities are increasingly supplied by **ATLAS-original models trained from random initialization**. It uses a well-organized external hierarchy of **verified facts AND tested reasoning procedures**. It can eventually interpret a request, inspect a project, retrieve evidence, plan steps, ask specialized models and tools for help, independently test a result, deliver useful work and retain genuinely useful lessons. Its software and models improve only through legitimate data and independent gates. Optional Qwen or other pretrained models are separately labeled references, not the system's permanent brain.

This is different from building a chatbot with buttons, a software IDE plugin or a list of 2,000 specialist names. Large role catalogs are a **future capability map**, not thousands of required model files. A successful native-model claim requires its weights, dataset, held-out comparison, useful downstream contribution and independent review. The original 65-parameter source specialist and 37-parameter Primary are a starting point, not a completed AI assistant.

## What you should eventually be able to do

**Ask ATLAS:** Have a local conversation about your permitted documents or projects, with clear differentiation between a fully ATLAS-original response, an exact deterministic answer, a cited source fact and a separately opted-in pretrained reference answer. It should know when it lacks evidence. It should be easy to find the original citation and correct a claim.

**Work on a project:** Select an authorized code/game/writing/creative project. ATLAS maps the actual files, versions and constraints, explains what exists, proposes complete code or editable artifacts, gives exact insertion/integration instructions, and later—only after a qualified guest and owner authorization—tests patches independently and offers reversible updates. Long-term languages include Unreal C++/Blueprint, UEFN Verse, Unity C#, Blender Python, Python, C/C++/C#, Rust and web technologies.

**Research:** In bounded offline mode, gather evidence from supplied files, compare competing claims, flag contradictions and stale source revisions, and preserve verified findings. In future, isolated owner-approved internet research may acquire public information, challenge it, and add only verified claims/procedures to reusable knowledge. Never assume a webpage or model reply is inherently true.

**Improve a Model:** Choose a weakness, authorized dataset, original model architecture, safe resource budget and test protocol. See real training, checkpoint and error metrics; compare new and old models on unfamiliar projects; review why a candidate was rejected or accepted. An eventual approved idle Training Director should choose worthwhile experiments without using personal secrets or starving the foreground PC.

**Create:** Beyond code, long-term specialists should produce usable sprites, assets, stories, documents, 3D systems and game workflows with actual output files and format validation. PLATZ Engine remains a **separate** creative platform, potentially interoperating later through a narrow versioned interface.

**Keep personal information private:** Private Playground should retain no ATLAS-side chat content; Personal ATLAS should be an explicit opt-in encrypted memory with correction/export/deletion and strict category scopes. A project question does not grant general memory retention or training permission. Never use your identity, accounts, real money, payment methods or subscriptions for autonomous tasks.

## How to use the full master without getting lost

The canonical file is **73,432 words**, with numbered Chapters 1–192 across Parts I–XXIII, Appendices A–W, and full historical source archives in the transfer package. Use the Word Navigation Pane (Headings) for reading, or open the Markdown chapter index `indexes/ATLAS_MASTER_INDEX.json` and find a chapter ID such as `CH-172` for model/data provenance. The chapter index gives exact start/end lines and SHA-256 digests to check that content was not silently changed. `ATLAS_REQUIREMENTS_TRACE.csv` preserves all 50 historical requirement IDs, plus new v3.3 targets, but the live repository must fill code/test/review fields before declaring anything verified.

**For your external developer sessions:** Attach the complete transfer ZIP once, tell Sol to read its canonical file and `prompts/SOL_INSTALL_AND_NEXT_021_025.md`, then use the shorter handoff prompt in subsequent turns after Sol has actually installed the documents into the Windows repo. When Sol finishes a batch, send Argon its brief reviewer trigger. Neither should message or wait for the other via Computer Use. Keep prior ZIPs/masters available for historical verification, not as competing live instructions.

**The single question to ask after each batch:** *What previously impossible real task can ATLAS-original learned weights now complete correctly without pretrained inference, and how does it compare against host-only and strong simple models on unfamiliar data?* If there is no verified improvement, demand an accurate root-cause explanation and the next evidence-based experiment—not a more impressive model name.

## Permanent boundaries

- The host and actual owner permissions override every model, file, web document, training example and retrieved instruction.
- No unauthorized real-money purchases, personal accounts, account sessions, subscription/free trials, owner identity or personal-data exposure.
- No self-promotion of models, fabricated owner feedback or tampering with protected evaluation.
- No executing arbitrary generated/downloaded code on the physical Windows host; no unsafe sandbox fallback.
- No autonomous online registrations/downloads without separately approved remote isolation and explicit scope; never claim perfect anonymity.
- Preserve legacy ATLAS, PLATZ Engine and FORGE as separately governed projects.
- Only independently verified facts/procedures enter trusted reusable knowledge, and only qualified original models receive authority in defined domains.
